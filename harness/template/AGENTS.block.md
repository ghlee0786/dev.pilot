## Pilot(하네스) — 에이전트 공통 규칙 (이 블록은 `node harness/cli.js install` 이 관리한다)

### 자율
- 되돌릴 수 있는 일(파일 편집 · 로컬 테스트와 빌드 · 읽기 전용 명령)은 묻지 말고 한다.
- 되돌릴 수 없거나 밖으로 나가는 일(push · 사용자 브랜치 병합 · 삭제 · 외부 시스템 쓰기 · 비밀 다루기)은 완성된 결과를 보여 주고 한 번만 승인받는다.
- 무엇이 끝인지 처음에 정하고 끝날 때까지 간다 — 중간 요약이나 "계속할까요?" 로 멈추지 않는다. 결과를 바꾸는 갈림길도 묻지 않고 지시에 가장 맞고 나중에 바꾸기 쉬운 쪽을 고르고, 끝난 뒤 보고에 "분기점 · 고른 것 · 이유 · 결과" 로 정리한다.
- 코드는 목표에 필요한 최소한만 쓴다 — 요청 밖 기능 · 옵션 · 한 번 쓰는 추상화 금지 · 표준 라이브러리와 기존 헬퍼 우선 · 바꾼 줄은 모두 요청으로 이어진다(관계없는 정리 · 리팩터 금지) · 자기 변경이 만든 미사용 코드만 지운다. 대답 · 보고는 결론 먼저, 짧게. 일을 시작할 때 이 세션의 스킬 · MCP 목록에서 그 일에 맞는 것을 먼저 고른다(라이브러리 문서 → context7 · Microsoft Learn, 코드 탐색 → LSP, UI · 문서 형식 → 해당 스킬). 이 저장소에 맞는데 없는 도구는 `node harness/cli.js toolkit` 으로 보고 사용자에게 제안만 한다 — 설치 · 설정 변경은 사용자가 정한다.

### 언어
- 사람이 읽는 것(대답 · 진행 보고 · 요약 · 문서 · 커밋 메시지)은 **사용자가 쓰는 언어**로 쓴다 — 이 사용자는 한국어. 작업 도중 영어로 바꾸지 않는다. 식별자 · 명령 · 경로 · 원문 인용은 그대로 둔다.

### git
- git 쓰기는 하네스를 거친다. 사용자 브랜치로의 병합 · push · 브랜치 삭제는 사용자가 명시적으로 말한 뒤에만 한다 — 병합은 `node harness/cli.js accept <id>`(여럿은 `batch`), push 는 `node harness/cli.js push [<remote>] [<branch>]`(빨리감기만 · 강제 없음). `git push` 를 직접 쓰지 않는다(훅이 막는다). 백그라운드 세션(`claude --bg`)도 push 하지 않는다 — git 은 하네스가 한다.
- `git reset --hard`(와 커밋을 옮기는 reset) · `git clean -f` · `git checkout -- .` · `git rebase` · 직접 `git merge`(`--ff-only` 포함) · `git pull` · `git stash` · `git commit --amend` 는 쓰지 않는다(훅이 막는다). 되돌리기는 `git revert`. MCP 의 git · GitHub 쓰기 도구도 셸의 같은 명령처럼 막힌다.
- 모든 작업은 커밋으로 끝난다. **자기가 고친 파일만** 경로로 지정해 커밋한다: `git add -- <파일>` → `git commit -m "<무엇을 왜>" -- <파일>`. `git add -A` · `git add .` 는 쓰지 않는다.
- 다른 세션 · 사람의 미커밋 변경은 건드리지 않는다(stash · 되돌리기 · 커밋 모두) · 비밀 파일(`.env*` · `*.pem` · `*.key` · `id_rsa*` · `.npmrc` · `credentials*` · `*.tfstate` · `service-account*.json`)은 커밋하지 않는다.

### 여러 세션 · 격리
- 한두 줄 수정 · 질문 · 조사, 그리고 같은 체크아웃에서 다른 세션이 일하지 않을 때의 작업은 그 자리에서 하고 고친 파일만 커밋한다.
- 같은 체크아웃에서 다른 세션이 일하고 있거나(board 훅이 알린다), 여러 세션이 도는 중에 여러 파일에 걸친 일을 하면 자기 레인을 만든다: `node harness/cli.js start "<요청 원문>"` → 나온 worktree 에서 세션을 열어 일하고 진행하며 커밋한다. 이전 작업을 이어 갈 때는 처음부터 다시 하지 말고 `start --from <id>`(그 브랜치에서 시작).
- 끝난 레인은 `accept <id>`, 여럿은 `batch <id>...` 로 묶어 검사를 한 번만 돌리고 `batch accept <bid>` 로 병합한다(사용자가 말한 뒤). 병합 중 충돌이 나면 그 레인에 병합이 남는다 — 그 레인에서 충돌을 풀고 커밋한 뒤 다시 accept.
- 사람 없이 맡길 일은 Claude Code 백그라운드 세션(`claude --bg "<요청>"`)으로 — 끝나면 그 브랜치를 accept 한다. 다른 세션에 알릴 것(무엇이 들어갔는지 · 같은 파일을 고친다)은 세션 간 메시지(`SendMessage` · `/list-agents`)로 보낸다. 서로 독립적인 일(조사 · 시나리오 시험 · 검토 · 서로 다른 파일)은 서브에이전트로 나눠 한 메시지에서 동시에 띄운다 — 같은 파일을 고치는 일은 나누지 않는다.
- 현황 `node harness/cli.js status`(레인 · 산 세션 · 겹치는 파일 · 주인 없는 미커밋 변경) · 취소 `cancel <id>` · 되살리기 `restore <id>` · 정리 `gc`(끝난 작업 — 하네스가 만든 것만).

### 하네스 보고 (자동)
- 하네스가 오류로 멈추거나 · 의도와 다르게 행동하거나 · 더 나은 방향이 보이면 묻지 말고 올린다: `node harness/cli.js report --kind <bug|intent|improve> --title "<한 줄>" --body "<무엇을 하던 중 · 하네스가 어떻게 했고 · 어떻게 되길 기대했나>"`. 사용자의 건의도 이렇게 올린다. **하네스 동작만** 쓴다 — 프로젝트 코드 · 이름 · 경로 · 비밀 · 작업 내용은 쓰지 않는다(경로 · 이름은 자동으로 가리지만 처음부터 쓰지 않는다). 하네스 예외는 하네스가 스스로 기록해 올린다.

### 할 수 없을 때
- 사용자 없이는 더 나아갈 수 없거나 의도적으로 보호된 것에 막혔을 때만 멈추고 이유 · 시도한 것 · 필요한 것을 그대로 보고한다. 검사를 통과시키려고 테스트를 지우거나 고치지 않는다. 할 수 없으면 할 수 없다고 쓴다.

### 검증
- 완료 신호는 저장소에 원래 있는 테스트 · 빌드 명령의 종료 코드다(사용자가 준 검사가 있으면 그것). 따로 검증 단계를 만들지 않는다. 병합(accept · batch)은 그 검사를 한 번 돌려 작업 전보다 나빠졌을 때만 막는다.
- 프로젝트 블록에 `lint_command` 가 있으면 끝내기 전에 그것도 돌려 통과시킨다(`{files}` 는 고친 파일 목록). 규칙을 끄거나 무시 주석으로 넘기지 않는다. "끝났다" 고 말할 때는 돌린 명령과 결과(통과 · 실패 수)를 함께 적는다 — 돌리지 않았으면 "확인하지 않았다" 고 쓴다.
